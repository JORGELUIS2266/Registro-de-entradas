Marco Teórico

2.1 Sistemas de Información

Un sistema de información es un conjunto de elementos organizados que interactúan entre sí para procesar datos y producir información útil para la toma de decisiones. Según Laudon & Laudon (2020), un sistema de información puede definirse técnicamente como un conjunto de componentes interrelacionados que recopilan, procesan, almacenan y distribuyen información para apoyar la toma de decisiones y el control de una organización. En el contexto del presente proyecto, el Sistema de Control de Entradas actúa como un sistema de información transaccional que centraliza los datos de alumnos y profesores del Instituto Tecnológico de Tlaxiaco.

2.2 Aplicaciones de Escritorio

Una aplicación de escritorio es un programa de software diseñado para ejecutarse localmente en una computadora personal, sin necesidad de un navegador web. Este tipo de aplicaciones tienen acceso directo a los recursos del sistema operativo y hardware, lo que les permite ofrecer mejor rendimiento, mayor capacidad de procesamiento y funcionalidad sin depender de una conexión a Internet continua.

El presente sistema fue desarrollado como una aplicación de escritorio utilizando Windows Forms con el lenguaje de programación C# sobre el framework .NET 4.7.2, lo que garantiza compatibilidad con el sistema operativo Windows instalado en los equipos del plantel educativo.

2.3 Lenguaje de Programación C#

C# (pronunciado "C sharp") es un lenguaje de programación orientado a objetos, de tipado fuerte, desarrollado por Microsoft como parte de la plataforma .NET. Fue diseñado para ser simple, moderno, flexible y orientado a la productividad del desarrollador. C# soporta los principales paradigmas de programación: orientado a objetos, funcional y orientado a componentes.

Sus características principales incluyen: manejo automático de memoria mediante el recolector de basura (Garbage Collector), programación asíncrona con async/await, LINQ para consultas integradas al lenguaje, manejo de excepciones robusto y un ecosistema extenso de librerías a través de NuGet. En este proyecto, C# fue utilizado para implementar toda la lógica de negocio, la capa de acceso a datos y la interfaz gráfica del sistema.

2.4 Windows Forms (WinForms)

Windows Forms es una plataforma de interfaz gráfica de usuario (GUI) incluida en .NET Framework. Proporciona un conjunto de controles visuales (formularios, botones, cuadros de texto, grillas de datos, etc.) que permiten construir aplicaciones de escritorio de manera rápida. Cada formulario (Form) en Windows Forms es una ventana que puede contener controles, manejar eventos y ejecutar lógica de negocio.

En el sistema desarrollado, Windows Forms fue empleado para crear todas las pantallas: Login, Menú Principal, Gestión de Alumnos, Gestión de Profesores, Listas de Consulta y Gestión de Usuarios, aprovechando el diseñador visual de Visual Studio para un desarrollo ágil de la interfaz.

2.5 Base de Datos

Una base de datos es una colección organizada y estructurada de datos almacenados electrónicamente en un sistema computacional. Las bases de datos son administradas por Sistemas Gestores de Bases de Datos (SGBD), que proporcionan mecanismos para almacenar, recuperar, actualizar y gestionar datos de forma eficiente, segura y confiable.

Las bases de datos relacionales organizan los datos en tablas (relaciones) compuestas por filas (registros) y columnas (atributos), y utilizan el lenguaje SQL (Structured Query Language) para la manipulación y consulta de datos. Este modelo garantiza la integridad referencial entre tablas mediante el uso de llaves primarias y foráneas.

2.6 Microsoft SQL Server

Microsoft SQL Server es un sistema gestor de bases de datos relacionales (SGBDR) desarrollado por Microsoft. Es ampliamente utilizado en entornos empresariales por su robustez, escalabilidad, seguridad y capacidades avanzadas de administración. SQL Server ofrece características como transacciones ACID, procedimientos almacenados, triggers, vistas, índices y replicación de datos.

Para el presente proyecto se utilizó SQL Server Express 2019/2025, que es la versión gratuita de SQL Server, ideal para aplicaciones de pequeña y mediana escala. La instancia se configuró como .\SQLEXPRESS en el servidor local, con autenticación mixta (Windows y SQL Server) para permitir conexiones remotas desde equipos en red.

La base de datos del proyecto, denominada entradas_tecnologico, contiene las siguientes tablas principales:

  • alumnos: Almacena el número de control, nombre, apellido, carrera, correo, semestre, grupo e imagen del alumno.
  • profesores: Contiene el ID, cédula profesional (RFC), nombre, apellido, teléfono, correo y sexo del docente.
  • usuarios: Gestiona las credenciales de acceso al sistema, incluyendo rol, estado de conexión y última sesión.

2.7 ADO.NET y Conexión a Base de Datos

ADO.NET (ActiveX Data Objects for .NET) es la tecnología de acceso a datos de Microsoft para aplicaciones .NET. Proporciona un conjunto de clases que permiten conectarse a fuentes de datos, ejecutar comandos SQL y recuperar resultados. Los componentes principales utilizados en el proyecto son:

  • SqlConnection: Establece la conexión con SQL Server mediante una cadena de conexión (Connection String).
  • SqlCommand: Ejecuta comandos SQL (SELECT, INSERT, UPDATE, DELETE) o procedimientos almacenados.
  • SqlDataAdapter: Actúa como puente entre la base de datos y un DataTable, llenando este último con los resultados de una consulta.
  • DataTable: Representa una tabla de datos en memoria, utilizada para mostrar información en controles DataGridView.

2.8 Arquitectura Cliente-Servidor

La arquitectura cliente-servidor es un modelo de diseño de software que divide las tareas entre proveedores de recursos o servicios (servidores) y los que los solicitan (clientes). En esta arquitectura, el servidor centraliza los datos y la lógica de negocio, mientras que los clientes proporcionan la interfaz de usuario y envían solicitudes al servidor.

El sistema desarrollado implementa esta arquitectura de la siguiente manera: una PC actúa como servidor ejecutando SQL Server con la base de datos, mientras que otras PCs en la red actúan como clientes ejecutando el ejecutable de la aplicación Windows Forms. La comunicación se realiza a través del protocolo TCP/IP en el puerto 1433 (puerto estándar de SQL Server).

2.9 Cómputo en la Nube

El cómputo en la nube (Cloud Computing) es un modelo de prestación de servicios de tecnología de la información que permite el acceso ubicuo, conveniente y bajo demanda a un conjunto compartido de recursos informáticos configurables (redes, servidores, almacenamiento, aplicaciones y servicios) que pueden aprovisionarse y liberarse rápidamente con un mínimo esfuerzo de gestión o interacción con el proveedor del servicio (NIST, 2011).

Los modelos de servicio en la nube se clasifican en:

  • IaaS (Infrastructure as a Service): Provisión de infraestructura virtualizada como máquinas virtuales, almacenamiento y redes. Ejemplos: Amazon EC2, Google Compute Engine, Microsoft Azure VMs.
  • PaaS (Platform as a Service): Entorno de desarrollo y despliegue gestionado. Ejemplos: Google App Engine, Heroku, Azure App Service.
  • SaaS (Software as a Service): Software listo para usar accesible desde el navegador. Ejemplos: Gmail, Microsoft 365, Salesforce.

2.10 Servidores en la Nube: Heroku

Heroku es una plataforma de computación en la nube como servicio (PaaS) que permite a los desarrolladores desplegar, gestionar y escalar aplicaciones. Fue fundada en 2007 y adquirida por Salesforce en 2010. Heroku soporta múltiples lenguajes de programación como Ruby, Java, Node.js, Python, PHP, Go y Scala.

Heroku simplifica el proceso de despliegue al abstraer la infraestructura subyacente. Los desarrolladores solo necesitan enviar su código mediante Git, y Heroku se encarga del aprovisionamiento, configuración y escalado del servidor. Utiliza el concepto de Dynos (contenedores ligeros) para ejecutar las aplicaciones y ofrece un ecosistema de complementos (add-ons) para bases de datos, caché, monitoreo y más.

En el contexto de este proyecto, aunque el sistema fue implementado en una arquitectura local/red, Heroku representa una alternativa viable para un futuro despliegue en la nube, donde la base de datos SQL Server podría migrarse a un servicio gestionado como Azure SQL Database o Amazon RDS for SQL Server, y la aplicación convertirse en una aplicación web accesible desde cualquier dispositivo con navegador.

2.11 Otros Proveedores de Nube Relevantes

Durante el desarrollo del proyecto se evaluaron opciones de alojamiento en la nube como alternativa a la arquitectura local:

  • Google Cloud SQL: Servicio de base de datos relacional gestionado de Google Cloud Platform. Compatible con SQL Server, MySQL y PostgreSQL. Se configuró una instancia de prueba con IP pública 35.232.208.144 para evaluar la conectividad remota del sistema.
  • Microsoft Azure SQL Database: Servicio de base de datos SQL Server totalmente gestionado en la nube de Microsoft, con alta disponibilidad, copias de seguridad automáticas y escalabilidad elástica.
  • Amazon RDS: Servicio de base de datos relacional de AWS que admite SQL Server, permitiendo administración simplificada de parches, backups y replicación.

2.12 Seguridad en Sistemas de Información

La seguridad de la información abarca las prácticas, políticas y controles implementados para proteger los datos contra accesos no autorizados, pérdida, modificación o divulgación. En el sistema desarrollado, la seguridad se implementó en múltiples niveles:

  • Autenticación: Sistema de login con verificación de credenciales (usuario y contraseña) contra la base de datos.
  • Autorización basada en roles: Dos niveles de acceso diferenciados: superusuario (acceso completo) y usuario estándar (acceso restringido a funciones de consulta y registro).
  • Control de sesiones: Seguimiento en tiempo real del estado de conexión de los usuarios (en línea/desconectado) y registro de la última conexión.
  • Validación de entradas: Validaciones en el frontend que previenen la inserción de datos incorrectos o maliciosos.
  • Consultas parametrizadas: Uso de parámetros SQL (@parametro) en todos los comandos de base de datos para prevenir inyección SQL.

2.13 Programación Orientada a Objetos

La Programación Orientada a Objetos (POO) es un paradigma de programación que organiza el software en torno a objetos, que son instancias de clases. Una clase es un molde que define atributos (datos) y métodos (comportamientos). Los cuatro pilares de la POO son: encapsulamiento, herencia, polimorfismo y abstracción.

En el desarrollo del sistema, la POO se aplicó estructurando el código en clases especializadas: Config (configuración de conexión), BaseDeDatos (capa de acceso a datos con métodos estáticos para cada operación CRUD), Session (gestión de la sesión del usuario activo) y Validaciones (lógica de validación de entradas), junto con las clases de formularios Windows Forms para la presentación.

2.14 Control de Versiones con Git y GitHub

Git es un sistema de control de versiones distribuido que permite a los desarrolladores rastrear cambios en el código fuente, colaborar con otros desarrolladores y gestionar diferentes versiones del software. GitHub es una plataforma en línea basada en Git que facilita el alojamiento de repositorios, revisión de código y colaboración en equipo.

Durante el desarrollo del proyecto, Git y GitHub fueron utilizados para el control de versiones del código fuente, permitiendo mantener un historial de cambios, gestionar ramas de desarrollo para nuevas funcionalidades y realizar respaldos seguros del proyecto en la nube.
