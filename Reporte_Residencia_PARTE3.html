Desarrollo

3.1 Metodología de Desarrollo

El proyecto se desarrolló siguiendo una metodología incremental e iterativa, en la cual el sistema fue construido por módulos funcionales de manera progresiva. Cada iteración incluyó las fases de análisis de requerimientos, diseño, implementación y pruebas. Este enfoque permitió identificar y corregir errores de forma temprana, así como incorporar mejoras y ajustes conforme avanzaba el desarrollo.

3.2 Arquitectura del Sistema

El sistema sigue una arquitectura de tres capas (Three-Tier Architecture):

  • Capa de Presentación (Frontend): Formularios Windows Forms (C#) que constituyen la interfaz gráfica de usuario. Contiene los formularios: Login, Menú Principal, Ingresar Alumno, Modificar Alumno, Eliminar Alumno, Lista Completa de Alumnos, Ingresar Profesor, Modificar Profesor, Eliminar Profesor, Lista de Profesores y Gestión de Usuarios.
  • Capa de Lógica de Negocio (Backend): Clases estáticas que encapsulan la lógica del sistema: Config.cs (gestión de cadenas de conexión por modo), BaseDeDatos.cs (operaciones CRUD), Validaciones.cs (reglas de validación de datos) y Session.cs (control de sesión activa).
  • Capa de Datos: Base de datos relacional SQL Server Express con la base de datos entradas_tecnologico.

3.4 Requisitos Funcionales

Los requisitos funcionales describen el comportamiento específico que el sistema debe realizar:

RF-01: Autenticación de Usuarios

El sistema debe permitir el inicio de sesión mediante usuario y contraseña. Debe verificar las credenciales contra la base de datos y otorgar acceso según el rol asignado. Debe registrar la fecha y hora del último inicio de sesión y marcar al usuario como conectado.

RF-02: Gestión de Alumnos

  • RF-02.1 Registro: El sistema debe permitir ingresar nuevos alumnos capturando: número de control, nombre(s), apellidos, carrera, correo, semestre, grupo y fotografía (opcional, en formato Base64).
  • RF-02.2 Consulta: El sistema debe mostrar la lista completa de alumnos registrados con funcionalidad de búsqueda por nombre, número de control, carrera o grupo.
  • RF-02.3 Modificación: El sistema debe permitir actualizar cualquier campo del registro de un alumno existente.
  • RF-02.4 Eliminación: El sistema debe permitir eliminar el registro de un alumno, previa confirmación del usuario.
  • RF-02.5 Exportación: El sistema debe permitir exportar la lista de alumnos a un archivo de Excel (.xlsx).

RF-03: Gestión de Profesores

  • RF-03.1 Registro: El sistema debe permitir ingresar nuevos profesores con: ID, RFC/cédula profesional, nombre(s), apellidos, teléfono, correo y sexo. El RFC debe ser único en el sistema.
  • RF-03.2 Consulta: El sistema debe mostrar el listado de profesores con búsqueda por nombre, correo, ID o RFC.
  • RF-03.3 Modificación: El sistema debe permitir actualizar los datos de un profesor existente, validando que el RFC no esté duplicado.
  • RF-03.4 Eliminación: El sistema debe permitir eliminar el registro de un profesor con confirmación previa.

RF-04: Gestión de Usuarios del Sistema

  • RF-04.1: El superusuario debe poder crear nuevos usuarios del sistema asignándoles rol, nombre completo y credenciales.
  • RF-04.2: El superusuario debe poder activar o desactivar cuentas de usuario.
  • RF-04.3: El superusuario debe poder eliminar usuarios registrados.
  • RF-04.4: El sistema debe mostrar en tiempo real qué usuarios están conectados y cuándo fue su última conexión.

RF-05: Control de Acceso por Roles

El sistema debe restringir el acceso a módulos según el rol del usuario autenticado. El rol "usuario" solo podrá acceder a consultas y registros. El rol "superusuario" tendrá acceso total incluyendo gestión de usuarios y eliminaciones.

RF-06: Configuración de Conexión

El sistema debe permitir operar en tres modos de conexión configurables desde código: local (SQL Server en la misma PC), red (cliente-servidor por IP en red local) y nube (servidor remoto en internet).

3.5 Requisitos No Funcionales

RNF-01: Rendimiento

El sistema debe cargar cualquier lista de datos en un tiempo menor a 3 segundos bajo condiciones normales de red local. Las operaciones de inserción, actualización y eliminación no deben tomar más de 2 segundos.

RNF-02: Disponibilidad

El sistema debe estar disponible durante el horario de operación del plantel (7:00 a 22:00 horas). El servidor de base de datos debe configurarse para iniciarse automáticamente con el sistema operativo.

RNF-03: Usabilidad

La interfaz debe ser intuitiva y accesible para personal administrativo sin conocimientos técnicos avanzados. Los mensajes de error deben ser claros, descriptivos y en español. Los formularios deben incluir validaciones en tiempo real con retroalimentación visual.

RNF-04: Seguridad

Todas las consultas a la base de datos deben utilizar parámetros SQL para prevenir inyección SQL. Las credenciales de conexión a la base de datos no deben ser visibles en la interfaz de usuario. El acceso a módulos administrativos debe estar restringido por rol.

RNF-05: Mantenibilidad

El código debe seguir el principio de separación de responsabilidades, organizando la lógica en capas independientes (presentación, negocio y datos). Cada módulo debe ser independiente para facilitar futuras modificaciones sin afectar al resto del sistema.

RNF-06: Portabilidad

El ejecutable del sistema debe funcionar en cualquier PC con Windows 10 o superior que tenga instalado .NET Framework 4.7.2 o superior, sin necesidad de instalar Visual Studio u otras herramientas de desarrollo.

RNF-07: Escalabilidad

La arquitectura del sistema debe permitir agregar nuevos módulos sin modificar la estructura existente. La capa de datos debe soportar el crecimiento del número de registros sin degradación significativa del rendimiento.

RNF-08: Compatibilidad

El sistema debe ser compatible con SQL Server Express 2017 o superior. La funcionalidad de exportación a Excel debe funcionar con Microsoft Office 2016 o superior.

Resultados

Al término del período de residencia profesional, se logró desarrollar e implementar un Sistema de Control de Entradas completamente funcional para el Instituto Tecnológico de Tlaxiaco. A continuación se presentan los resultados obtenidos por módulo:

4.1 Sistema de Autenticación

Se implementó exitosamente un módulo de login con validación de credenciales contra la base de datos SQL Server. El sistema diferencia correctamente entre los roles de superusuario y usuario estándar, redirigiendo a cada uno a su menú correspondiente con las funcionalidades habilitadas según su nivel de acceso. Adicionalmente, se implementó el registro automático de la última conexión y el monitoreo en tiempo real del estado de los usuarios (en línea/desconectado).

4.2 Módulo de Gestión de Alumnos

El módulo de alumnos quedó completamente operativo con las siguientes funcionalidades validadas:

  • Registro de nuevos alumnos con todos sus datos personales y académicos, incluyendo fotografía comprimida en Base64.
  • Lista completa con búsqueda dinámica en tiempo real por múltiples campos (nombre, número de control, carrera, grupo).
  • Modificación de registros existentes con pre-carga automática de datos en el formulario.
  • Eliminación segura con diálogo de confirmación.
  • Exportación de listas a Excel, organizadas por carrera y semestre.
  • Validación de formato en todos los campos: número de control alfanumérico, correo electrónico, semestre numérico y grupo con formato estándar.

4.3 Módulo de Gestión de Profesores

El módulo de profesores fue implementado con todas las operaciones CRUD funcionales. Se destacan los siguientes resultados:

  • Registro de profesores con asignación automática de ID correlativo y validación de RFC/cédula profesional único.
  • Validación del formato de RFC con 12 o 13 caracteres alfanuméricos.
  • Lista de profesores con búsqueda por nombre, correo, ID y RFC.
  • Modificación de datos con validación de RFC duplicado (excluyendo el propio registro).
  • Eliminación con confirmación y actualización inmediata de la lista.

4.4 Módulo de Gestión de Usuarios

El módulo de gestión de usuarios, exclusivo para el superusuario, permite administrar completamente las cuentas del sistema. Se logró implementar la visualización en tiempo real del estado de conexión de cada usuario, con actualización automática cada 30 segundos, mostrando el semáforo visual de estado (verde = conectado, gris = desconectado) y la fecha/hora de la última sesión.

4.5 Arquitectura de Conexión Configurable

Se desarrolló un sistema de configuración de conexión flexible mediante la clase Config.cs que soporta tres modos de operación: local, red y nube. Durante las pruebas, el sistema operó correctamente en modo local (SQL Server Express en la misma máquina) y en modo red con múltiples clientes conectados simultáneamente al servidor central a través de la IP de la red local.

Conclusión

El desarrollo del Sistema de Control de Entradas para el Instituto Tecnológico de Tlaxiaco representó una experiencia de aprendizaje integral que permitió aplicar, de manera práctica y en un entorno real, los conocimientos adquiridos a lo largo de la carrera de Ingeniería en Sistemas Computacionales.

Se logró cumplir con la totalidad de los objetivos planteados al inicio del proyecto: se diseñó e implementó una base de datos relacional robusta en SQL Server, se desarrollaron módulos CRUD completos para alumnos y profesores, se estableció un sistema de autenticación con control de acceso basado en roles, y se implementó una arquitectura cliente-servidor funcional que permite la operación del sistema desde múltiples estaciones de trabajo en red local.

Desde el punto de vista técnico, el proyecto permitió profundizar en el dominio de tecnologías ampliamente demandadas en la industria del software: el lenguaje C# y el ecosistema .NET, el manejo de bases de datos relacionales con SQL Server, la programación de interfaces gráficas con Windows Forms, el uso de ADO.NET para el acceso a datos, y los principios de arquitectura de software en capas. Asimismo, se adquirió experiencia práctica en el manejo de sistemas en red, configuración de servidores SQL y evaluación de alternativas en la nube como Google Cloud SQL y Heroku.

El sistema entregado resuelve de forma efectiva la problemática identificada en la institución, sustituyendo los procesos manuales de registro por una solución digital centralizada, segura y de fácil uso para el personal administrativo. La implementación de validaciones en tiempo real, la diferenciación de roles y el monitoreo de sesiones activas aportan valor adicional al sistema más allá del objetivo inicial.

Como trabajo a futuro, se recomienda migrar la aplicación a una arquitectura web para eliminar la necesidad de instalar el ejecutable en cada equipo cliente, integrar un módulo de generación de reportes estadísticos avanzados con gráficas, implementar el registro de entradas y salidas con código de barras o QR, y considerar el despliegue en la nube mediante plataformas como Azure o Heroku para garantizar la disponibilidad del sistema desde cualquier lugar.

En conclusión, la residencia profesional cumplió plenamente con su propósito formativo: consolidar competencias técnicas, desarrollar habilidades de resolución de problemas reales, fortalecer la capacidad de comunicación y documentación, y contribuir con una solución tecnológica de impacto positivo para la institución anfitriona.
